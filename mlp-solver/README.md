# Финальное решение и MLP V2

В `submission/` находятся все 98 файлов из `SUBMISSION_FINAL_T0_T7.zip` без изменений. Это готовый финансовый расчёт товарища с сохранёнными правилами. MLP в нём не вызывается.

В `src/` находится эксперимент из `MLP10M_V2_SOURCE.zip`. Он собирает небольшие программы из типизированного словаря, обучает MLP ранжировать промежуточные программы и проверяет поиск на новых синтетических задачах. Это отдельный эксперимент, его проценты не являются точностью t0–t7.

Архив SOURCE не содержит обученных весов из Colab. Полный прежний результат нельзя восстановить по одним исходникам. `runs/smoke` содержит только короткое локальное обучение для проверки запуска.

## Подготовка

На этом Mac окружение `.venv` уже установлено. На другой машине:

```sh
./setup.sh
./run.command doctor
```

Нужен Python 3.10 или новее, NumPy и PyTorch. Для применения NPZ-весов и поиска нужен только NumPy. PyTorch используется при обучении. `--device auto` выбирает CUDA при её наличии, иначе CPU. Apple MPS в этой сборке не используется.

## Проверка готового финансового решения

Из папки `mlp-solver`:

```sh
./run.command check-submission \
  --legacy /Users/danilarmolenko/Documents/HACK/LifewareChallenge/participants/legacy \
  --targets /Users/danilarmolenko/Documents/HACK/LifewareChallenge/participants/targets
```

Команда использует официальный `../starter_kit/check.py`. Журнал выполненной проверки находится в `runs/submission_check/check.log`. t5 выдаёт кандидатов в аномалии, полного эталона для F1 нет. Налоговые функции t7 входят в архив, но текущий checker t0–t5 их не оценивает.

## Проверка MLP и поиск формулы

```sh
./run.command check
./run.command smoke --out runs/smoke_new --device cpu
```

Короткий запуск использует 24 синтетические задачи, 2 эпохи на этап, затем проверяет поиск на 6 новых задачах. Это проверка исполнения всей цепочки, а не полноценное обучение или оценка качества.

Пример поиска по входам и выходам:

```sh
./run.command solve --task examples/commission.json --out runs/commission_heuristic
./run.command solve --task examples/commission.json \
  --mode hybrid --model runs/smoke/run1/models/round2/best.npz \
  --time-ms 3000 --out runs/commission_mlp
```

Результаты содержат `program.json`, читаемую формулу `formula.txt` и статистику `result.json`. Статус `fit` означает точное совпадение на переданных примерах. Перенос на новые входы проверяется отдельно.

Вычисление найденной программы:

```sh
./run.command predict --program runs/commission_heuristic/program.json \
  --args '[{"decimal":"2000"},{"decimal":"0.03"},{"date":"2026-10-18"}]'
```

Формат новой задачи показан в `examples/commission.json`: `input_types`, `output_type`, список `examples` с `args` и `y`. Поддерживаются до четырёх входов типов `money`, `date`, `int`, `bool`, `state`. Числа Decimal и даты задаются явно. Формула-эталон `ast` в поисковый вход не допускается.

## Полный эксперимент V2

```sh
./run.command pipeline --out runs/full_v2 --tasks 12000 --workers 4 --device auto
```

Основная сеть имеет ровно 10 000 000 параметров: `256 → 2078 → 2240 → 2144 → 2`. Сначала собираются обучающие примеры при эвристическом поиске, затем сеть обучается повторно на дополненных примерах собственного поиска. Малая контрольная сеть имеет 107 074 параметра.

Нормализация строится только по TRAIN. Выбор весов использует validation loss. Режим поиска выбирается на validation, после чего генерируется новый тест. Кандидаты проверяются на известных примерах и на 256 новых входах независимым Fraction-интерпретатором. Обучение использует известные синтетические подпрограммы; в рабочем поиске такой подсказки нет.

Полный CPU-запуск заметно дольше короткой проверки. На Colab GPU из сохранённого отчёта прежний запуск занял около 32 минут; это не прогноз для данного Mac. Лимиты обучения, число задач и бюджет поиска можно изменить через `./run.command pipeline --help`.

Результат записывается в `runs/full_v2`: веса `run1/models/{round1,round2,small}/best.npz`, метрики `evaluation/results.json`, архив `MLP10M_V2_RESULTS.zip`. Архив включает NPZ-веса, отчёты и код; сырые массивы обучения и `.pt` в него не входят. Существующий каталог запуска не перезаписывается.

Для повторного обучения без оценки есть `train`, для оценки готовых моделей `evaluate`; `--help` показывает параметры. `./run.command status` выводит состояния запусков.

## Импорт весов Colab

Если сохранился исходный архив результатов:

```sh
./run.command import-models --archive /path/to/MLP10M_V2_RESULTS.zip \
  --sha256 b6e152d61f25f861e0b1a2c3d10e11572193a96f36b9683fb27c433062e01658
```

Ожидаемый SHA выше относится к старому архиву, указанному в ноутбуке. Для нового архива используйте его SHA из `DOWNLOAD_READY.json`. Импорт проверяет формы массивов, число параметров, нормализацию и прямой проход NumPy. Он не исполняет код из ZIP. Доступные модели окажутся в `models/colab_v2`; укажите нужный `.npz` через `solve --model`.

## Состав и ограничения

- `reference/` сохраняет оба оригинальных архива.
- `IMPORT_MANIFEST.json` фиксирует SHA архивов, установленных файлов и список адаптированных исходников.
- `src/friend_primitives` содержит готовые функции товарища, включая округление по эпохам, календарь и финансовые переходы.
- Словарь, набор констант, длина программ до 9 узлов и обработка типов заданы заранее. MLP меняет приоритеты поиска, не добавляет неизвестные операции.
- Данные `legacy` и `targets`, окружение, веса и результаты не добавляются в Git.
- Финальное решение `submission/` и синтетический поиск `src/` пока не объединены в автоматическое восстановление всех финансовых алгоритмов.

Локальные изменения исходников нужны для CPU/CUDA, настраиваемых путей и бюджетов, проверки нормализации. Архитектура MLP, финансовые примитивы, признаки и исходный механизм поиска сохранены.
